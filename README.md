# SHV Digital landing page

React + Vite landing page with Portuguese, English and Spanish translations and build-time prerendering.

## Development

```sh
npm install
npm run dev
```

Language is determined by the URL: `/pt-BR/`, `/en/`, `/es/`. The root `/` uses Portuguese and points its canonical URL to `/pt-BR/`. Header flag links navigate to the corresponding language; no browser language or saved preference overrides shared URLs. Content lives in `src/i18n.js`.

The header language dropdown shows the current flag and language code. Its native disclosure works without JavaScript; with JavaScript, Escape and outside clicks close it. It supports keyboard navigation and reduced-motion preferences. The dropdown heading and accessible label follow the current page language.

Keep header links in page order on desktop and mobile: **Sobre → Diferenciais → Serviços** (English: About → Why SHV → Services; Spanish: Nosotros → Por qué SHV → Servicios). Update the anchor order and all translated labels together.

The header has an animated purple/blue border ring, a logo tilt/glow on hover or keyboard focus, and a color-flow/light-sweep contact button that never scales. Navigation highlights the section currently underneath the fixed header, using a purple pill, underline, and `aria-current="location"`; the contact button is highlighted in the contact section. Links remain visible in a second compact row on mobile. Section detection follows document order (About → Why SHV → Services → Contact), including direct hash links and the bottom of the page, rather than assuming navigation-link order. Reduced motion disables the ring and animated transforms/sweeps; forced-colors mode preserves borders and the active-location indication.

The ring has brighter moving purple/blue highlights on a two-pixel stroke and a six-second loop. Selected navigation items have a short light sweep and settling label animation. Clicking a header anchor immediately highlights only that destination during smooth scrolling, rather than flashing intermediate sections. Wheel/touch/scroll-key interruptions return to normal scroll tracking; a timeout prevents a stale destination lock. The logo uses the native `#inicio` anchor to return to the top without reloading or replaying the intro. Modified clicks and no-JavaScript anchor navigation keep their normal browser behavior. The language trigger, panel, selected row, and focus treatments share the same purple/blue palette and subtle light-sweep treatment.

Keep decorative background glows clipped inside their own layers to prevent horizontal overflow on mobile. Do not clip the header itself: its language dropdown must be able to extend below it. Check the header and open dropdown at narrow mobile widths in all three languages after layout changes.

## Adding or changing content

Every user-facing change must be provided in **Portuguese (Brazil), English, and Spanish** in the same update. Add matching translation keys in all three objects in `src/i18n.js`, including accessibility text and SEO metadata where applicable. Do not hardcode translated text in components. Repository-wide agent instructions are in `AGENTS.md`.

## Public URL (no configuration required)

**The default public URL is https://shvdigital.com.br/. No `.env` file is needed** for development or a production build on this domain. Missing or empty `SITE_URL` values use this default automatically.

Only if you need a different domain, copy `.env.example` to `.env` and change:

```dotenv
SITE_URL=https://your-other-domain.com
```

`SITE_URL` is public configuration, not a secret. It tells the build which full URLs to write into canonical links, language alternates, SHV logo social previews, structured data, `sitemap.xml`, and `robots.txt`. It does not publish the website or configure hosting. A deployment environment variable can also override the default. Use only an HTTP(S) origin, without a subpath, query, or fragment; a trailing slash is accepted and normalized internally to avoid double slashes.

The fallback is defined in `src/seo.js`. `scripts/prerender.mjs` reads the optional override for production, and `vite.config.js` uses it for development metadata. Rebuild after changing it.

## Production

Run the following commands—creating `.env` is **not required**:

```sh
npm test
npm run lint
npm run build
npm run test:build # optional: rebuild and validate the generated HTML
npm run preview
```

Deploy **all of `dist/`** to a static host that serves directory `index.html` files. The build generates `/index.html`, `/pt-BR/index.html`, `/en/index.html`, and `/es/index.html`, each with fully rendered localized content, language attributes, metadata, canonical/hreflang links, Open Graph/Twitter logo previews, and JSON-LD. React hydrates the existing HTML for interactions. `.prerender/` is an intermediate build directory, not a deployment artifact.

Serve the language directories before any SPA catch-all rewrite; rewriting every locale to the root HTML would return Portuguese metadata to crawlers. Prefer a real 404 for unknown paths. Lowercase `/en/` and `/es/` are the canonical public URLs; configure host redirects from `/EN/` and `/ES/` if those aliases are needed in production. Also redirect slashless URLs to their trailing-slash equivalents. If your host cannot serve directory indexes, add explicit rewrites from each locale to its own `index.html`.

`dist/sitemap.xml` and `dist/robots.txt` are generated using `SITE_URL`. Submit `/sitemap.xml` to search engines after deployment. Rebuild whenever translations or the production domain change.

### Services processor

Services entrances use `observeSettledEntrance`: they wait for a 240ms scrolling pause and at least half of the target (or half the available viewport for tall content) to be visible below the fixed header. Every scroll resets the wait; native `scrollend` is supported with the same debounced fallback. Header navigation therefore finishes before playback, while manual scrolling, direct fragment links, mobile, and tall sections use the same rule without scroll snapping or forced navigation. After hydration, `holdEntrance` prepares each animation paused at its first frame: text awaits its reveal. Playback resumes that same animation rather than resetting visible finished content. The board uses the same settled-scroll rule through `useProcessorEntrance`, with its poses in CSS (see below). Hero interruption cancels only Hero animations, not these prepared entrances. Visibility is rechecked at playback, and each entrance plays only once. The Services heading, board, and details are observed independently so lower content on mobile does not animate off-screen. Static HTML, reduced motion, and unsupported browsers retain visible content without prepared animations; interacting with a waiting processor cancels its prepared pose immediately.

The reading panel is a glass sheet inside the stage. From 960px it is absolutely positioned on the right, facing the reader, and hugs its content: swapping views never changes the stage height (fixed at 760px) or moves anything else. Below 960px it sits under the board at full width; the idle guide and the four single-service views share one CSS grid cell, so switching services does not resize the page (the all-services overview is taller and extends the panel when the core is activated). Browser scroll anchoring is disabled within the stage. The no-JavaScript layout remains a normal visible list of all four services. The panel swaps when the pulse arrives: the outgoing content fades over 150ms and the incoming blocks (icon, counter, title, text) enter 60ms apart. Its gradient edge and glow are on only while a service is active.

Activation is a pulse. Clicking a chip flashes the core and sends a bright purple-to-blue segment along that service's own trace in 600ms (`stroke-dashoffset`), leaving the trace lit behind it; on arrival the chip rises 12px, gains its gradient edge and glow, and a ring of light spreads across the board. The previously active service fades over 400ms. Activating the core raises it, fires the four pulses 150ms apart clockwise from 01, lights every chip, and then the secondary traces (`processor-backplane`). The shared timings are the `--travel` and `--stagger` custom properties plus `TRAVEL_MS`/`STAGGER_MS` in `src/utils/serviceCircuit.js`; keep them in step. Repeated activation replays the pulse. No focus movement or automatic scrolling is introduced.

The board starts with no selected service and no pressed button, but it never looks switched off: faint pulses travel each trace from the core every 1.9–2.9s out of phase, the light under the core breathes on a 4s cycle, a sparse third of the solder points twinkles, and the "awaiting activation" status dot keeps pulsing. After hydration the panel shows a localized `00 / 04` guide. Each service has its own trace leaving its own core pin. Without JavaScript, all four service descriptions remain visible instead of instructions for disabled controls.

Services shares Home's open ambient purple/blue background, glowing `//` label, responsive `WaveHeadline` heading, and readable system sans-serif body copy. The heading and every service detail use the same smoothly fading pointer spotlight; the heading copy reveals as one staggered group, independent of the board. A keyboard-revealed, localized pause/resume control stops ongoing text, icon, circuit, and ring animations without changing service selection. Reduced motion, forced colors, static visible HTML, and all three locales retain their existing fallbacks. Ambient layers are decorative and cannot intercept pointer events.

Standby loops begin after the board startup settles and pause while the board is offscreen, the document is hidden, or the Services pause control is on (which also makes activation an immediate state change). On desktop pointers (`useBoardPointer`), the board leans up to 5° towards the cursor with eased interpolation and a light follows the cursor over the surface, brightening the dot grid and nearby traces; hovering or focusing a chip raises it 6px and previews its trace at 50%. Touch and widths under 960px have no pointer effects. The detail glyph floats and glows gently while visible; mouse/pen movement over its tile tilts it by at most 12°. Reduced motion removes the startup, standby loops, and pointer tilt, and activation becomes a direct state change with a short text fade; forced colors keeps the static selected-state outline.

The board is a full-width stage in the same frame as About (`about-stage-shell`/`about-stage-frame`). From 960px it is tilted back (`rotateX(24deg)`, no diagonal turn, so the top row reads like the bottom one) under a long perspective with real `translateZ` heights: board (0), traces (2px), service chips (24px) and the SHV core (44px); their thickness is a stack of solid shadows (`--wall`) rather than extra 3D layers, and each casts a shadow on the board; below 960px the tilt drops to 6° with a 2×2 chip grid around the core. Geometry lives in `src/utils/serviceCircuit.js`: a landscape layout (from 1280px) and a portrait one, each generating the SVG traces (straight runs and 45° diagonals only), pins, solder points and the chip positions the CSS consumes. The untilted wrappers are `pointer-events: none` so they cannot cover chips on the far half of the board. `useProcessorEntrance` sets `data-startup` (`waiting` → `playing` → `done`) once scrolling settles: the board rises from flat into its pose, traces draw outwards, chips seat from above with a spring, and the core lights last, about 1.9s in total. Pointer/keyboard interaction, a width change, reduced motion, or hiding the page settles it immediately. Nothing on the 3D chain uses opacity, filters or clipping at rest, which would flatten the layers. For frame rate, the scene avoids anything the browser must recompute every frame: no `filter`/`backdrop-filter` blurs or SVG `drop-shadow`s (shadows and glows are gradients or painted box-shadows), the slab, chips and core get their sides from solid box-shadows instead of extra 3D layers, no animation runs on `filter`, and the circuit SVG only repaints during an activation. Standby pulses (`useCircuitRunners`) and twinkling solder points are small HTML lights on one flat plane above the traces, animated with `transform`/`opacity` only; the pointer hook writes transforms directly on the two moving elements instead of inherited custom properties. Static/no-JavaScript content stays in its final state.

Header links use native hash scrolling. The shared `.section-anchor` rule compensates for each section's top padding so content lands below the fixed header instead of leaving both a header offset and an empty padding gap. The same CSS applies to direct fragment URLs and no-JavaScript navigation. Active-section tracking uses the content edge and includes scroll margins when tracking a clicked destination. Direct fragment URLs are realigned once fonts and hydrated layout are ready, unless the user has already started navigating.

`#servicos` uses a CSS-3D circuit board with four service chips connected to the SHV core. Selecting a chip sends a pulse along its SVG trace, raises the chip, and shows its description in the reading panel. Selecting the core activates all four chips and shows all descriptions. Chips and core are native buttons with `aria-pressed`, in Tab order 01–04 then the core, with visible focus; the circuit SVG is decorative (`aria-hidden`) and the panel is an `aria-live="polite"` region that announces updates without moving focus. All four descriptions remain visible in prerendered/no-JavaScript HTML, with inert chip controls until hydration. Headlines, instructions, and accessibility labels are provided in all three languages. No WebGL, external assets, or additional dependencies are required.
